    CORPUS: 40 allow (plain + compound read-only) + 40 block (writes + evasions),

    mutated at a scratch path IN PLACE; the SAME already-answered command is
    asked again and the verdict must flip. Nothing is restarted — the module

    override and an allowing override). The same proof one level down against
    the CLI alone (the master plan's CR5 shape): copy CLI+contract to a scratch
    tree, mutate the copy, verdict differs; --contract selects the copy asked for.

(c) BOTH DIRECTIONS: the truth corpus asserts allow AND block cases; the reload
    proof asserts a blocking mutation AND a permissive mutation.

-------------------------------------------
The first green run was 82 passed / 2 failed, and both failures were bugs in the
TEST, not the product — recorded because they are findings about the seams:
  1. the --contract assertion built its path from the CLI FILE instead of the
     scratch tree root, so it asked for a path under a file;
  2. the fail-closed test deleted the scratch contract and expected the CLI to
     report COULD NOT VERIFY — but the CLI's lookup falls back to the deployed
     copy under ~/.steadfaste-fleet/services, so a host with a deployed contract
     can never reach that branch. The test now points HOME at the scratch root
     for the child process, which is what makes the fail-closed branch reachable
     and asserted rather than assumed.

Both are documented in the test's docstrings as well.
