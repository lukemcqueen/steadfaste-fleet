## WHY THIS IS A MISHAP
The deploy root held the live .env plus SIX .env.* backups (~5.8 KB each, mode 600,
gitignored, none tracked). Each is an independent plaintext copy of the FULL secret
set — including the VictoriaMetrics basic-auth password — and nothing in the fleet
collected them: they accumulated from ad-hoc .env edits with no retention policy.
Seven independent exposure paths for one secret set is the defect; six of them
carried no information the seventh did not.

## PROVEN BEFORE DELETING (nothing of value lost)
1. No secret reached a TRACKED file:
   git grep -I -l -F $PW -- .   ->  0 files
   (PW = the running container's -httpAuth.password, extracted to a var, never echoed)
2. FOUR of the six backups declare NO key absent from the live .env — pure copies.
3. TWO (reviewer-max-tokens-20261018, dual-bak-20261113132648) declare 13 CORTEX_*
   keys that exist nowhere in the live .env (live .env has 0 CORTEX_ lines): a retired
   naming generation. grep for readers of CORTEX_BUS_URL/CORTEX_BASE/CORTEX_BUS_TOKEN/
   CORTEX_DOMAIN across *.sh *.py *.yaml *.yml finds NO code — only historical
   docs/evidence and docs/older/ archaeology. The generation is DEAD; its values are
   worthless to every runtime.
4. The KEPT backup covers EVERY live key and differs on only two:
   FLEET_BUS_URL, FLEET_BUS_FALLBACK_URL (the bus pair, re-anchored in the DB, not the file).
