## What this says (honest reading)

- **Cron compute is nowhere near the $10/day target.** Aggregate LIFETIME cron
  spend across all six hosts is **$280.05** — the fleet has never accumulated
  meaningfully against a $10/day run-rate on cron compute. Confirms, not rejects,
  the prior baseline's verdict.
- **Interactive spend is the real driver, and it is concentrated on esther.**
  Langfuse reports a 7-day trace total of $88.36 on esther alone (≈$12.6/day
  cron+interactive), $10.49 on gisu, $7.70 on kustos. Three hosts (moses,
  joseph, titus) report zero Langfuse traces for the window — joseph/titus/moses
  run no local interactive surface that reports through this Langfuse daily
  endpoint, so their interactive spend is NOT zero, just not measured here.
  (joseph returned HTTP 401 / titus no instance on the 10-26/27 run; same gap
  shape repeats.)

## Coverage (not implied, stated)

- **Cron tokens/fires + lifetime cron $: 6 of 6 hosts** (measured, re-runnable).
- **Interactive spend: 3 of 6 hosts** (esther, gisu, kustos) via Langfuse. The
  other three report no traces — a GAP, never a zero.
- **Per-day cron $ (the $0.64/day-style daily figure) is NOT in this instrument**:
  `cron-cost-metrics.py --json-summary` emits lifetime + per-day token/fire
  counts, not per-day $ spend. Per-day cron $ comes from
  `orch-weekly-cost-report.py --days 7` (reads state.db `source='cron'` per day),
  which reads THIS host's state.db only. A per-host per-day cron $ breakdown
  would additionally need that instrument run on each worker host; it is not
  fabricated here from lifetime totals.
