## Independent review (cycle 14752) and folding

The pro reviewer (deepseek-v4-pro) returned FINDINGS — two medium findings, both
about the scanner being able to report clean without scanning a file:

- ADV-14752-1 (swallowed-error): `except OSError` returned clean, so an
  unreadable tracked file would pass silently.
- ADV-14752-2 (unverified-claim): the "skip binary (NUL in first 8k)" heuristic
  could hide a deny-listed identifier later in such a file.

Both folded:

- On ANY read failure the file now returns a `READFAIL` finding, so the guard
  FAILS on a file it cannot verify — never reports clean.
- `test_scanner_sees_the_sanctioned_repo_url_context` now asserts
  `visited == len(git ls-files)` — no file is excluded by a heuristic without
  failing the positive control.
- The binary-skip heuristic was REMOVED; every tracked file is swept.
- A tracked-but-worktree-deleted file (still in the index, absent on disk —
  a pending deletion or sparse checkout) is read from its index blob via
  `git show :<path>`, because the tracked surface IS the index; only a file
  absent from both index and worktree is a true READFAIL.
