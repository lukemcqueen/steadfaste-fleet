    migrate-victoria-data: cleanup 3/3: removing the stale parent dir if it is now empty
    migrate-victoria-data: done — stale dir removed, container live on <HOME>/.steadfaste-fleet/victoria-data

  Note the ORDER, which is the whole point of that script: the data is MOVED
  (atomic, one filesystem) not copied; the container is verified against startup
  markers and a settle window BEFORE anything is removed; the rollback container
  is destroyed before the old data dir, so an interruption can never leave the
  data gone while a rollback path still appears to exist. Compare the copy I
  attempted earlier in this session, which the integrity gate correctly rejected
  as a mid-write snapshot (134 files/1.1M vs 457/4.0M) because the live TSDB was
  still writing — that is why the move, not a copy, is the design.
