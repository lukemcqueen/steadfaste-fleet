FINDING: the pi path was NOT DRY — it silently ignored the fleet env file.
-------------------------------------------------------------------------
* reviewer-agent-pi.sh resolves its model as
    MODEL="${ADVERSARIAL_REVIEWER_MODEL:-deepseek/deepseek-v4-pro-0813}"
  i.e. ONLY from its own process env, falling back to a hardcoded literal.
* The close gate (_call_reviewer_agent in mcp-servers/loop-gov-mcp.py)
  spawned the command via subprocess.run(shlex.split(cmd), ...) with NO
  `env=` override, so the child inherited only the GATE's process env.
* Measured (real runtime): the running gate process had NO
  ADVERSARIAL_REVIEWER_MODEL in /proc/<pid>/environ, and the fleet env file
  (~/.steadfaste-fleet/.env sets ADVERSARIAL_REVIEWER_MODEL=
  "deepseek/deepseek-v4-pro-0813") was never visible to the script.
* Consequence: the pi backend worked today only because all three sources
  happened to equal deepseek/deepseek-v4-pro-0813. If REVIEWER_MODEL_DEFAULT
  changed (the whole point of the DRY constant), the pi path would keep the
  stale literal — the "changing the reviewer in one line" promise was false
  for the agent backend. The `openrouter/` prefix itself was ALREADY correct
  (pi accepts the bare deepseek/<model> id; default provider is openrouter).

FIX (this cycle)
----------------
mcp-servers/loop-gov-mcp.py  _call_reviewer_agent now builds the child env
    child_env = dict(os.environ)
    child_env["ADVERSARIAL_REVIEWER_MODEL"] = _reviewer_model()
  and passes env=child_env to subprocess.run. _reviewer_model() resolves
  process-env -> fleet env file -> REVIEWER_MODEL_DEFAULT, so the pi script
  now honors the SAME single source as the llm backend. The script's literal
  is now truly a last fallback.
