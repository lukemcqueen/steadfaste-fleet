Interpretation:

  • loop = 2460 → the dominant class. The sweep only SURFACES LOOP

  • pending = 7 → PENDING-leak signal; the sweep emits an alert if a
    PENDING row goes unscored for >24h without an active governance lock.
  • The precommit-fixture cleanup matched 0 — fixture artifacts are
    also already auto-overridden.

The existing sweep covers STOP_OK and precommit fixtures. The remaining
silent-fail backlog is dominated by LOOP cycles, which the sweep
correctly refuses to auto-close (a LOOP is "keep iterating", not
"done").

────────────────────────────────────────────────────────────────────────
5. Root cause hypothesis — pending-review pile-up
────────────────────────────────────────────────────────────────────────
The "pending review pile-up" is dominated by cycles that should have
triggered an adversarial review but didn't. Two compounding causes:

  (a) E1 wiring is PARTIALLY IMPLEMENTED. The review_class column was
      added (l.3690, 2026-11-10) and the classifier exists
      (_review_class, l.6973), but the close gate at end_change
      records review_class for only 2.6% of cycles. The classifier is
      only invoked from explicit end_change paths that pass
      has_uncommitted_code / paths context; most cycle close events
      don't carry that context, so the classifier returns None and
      the column stays NULL.

  (b) The complexity gate (50-line / 3-file threshold) still decides
      whether any review runs at all. A 30-line refactor of a security
      check is below threshold and gets skipped; a 60-line prose doc
      edit is above threshold and gets reviewed. The review cost lands
      on every complex-by-size cycle regardless of risk — exactly the
      failure mode that lever E was designed to fix.

  (c) The existing sweep (agent-review-queue-sweep.py) handles STOP_OK
      and precommit fixtures but is conservative on LOOP. A LOOP cycle
      with the same outcome_note across N iterations (a stalled
      worker) is surfaced for human review rather than auto-accepted,
      so it accumulates.

6. Proposed stage-1 fix (single, smallest measurable)
────────────────────────────────────────────────────────────────────────
From the documented remedy list (docs/older/review-queue-diagnosis-2026-10.md
§"Cheapest remedy"), the cheapest measurable fix that targets the actual
silent-fail set (LOOP-dominated, not the parked class) is:

  STAGE-1 FIX: add a "stalled LOOP" detection to the existing sweep —
  when a LOOP cycle has the SAME outcome_note across N>=3 iterations
  (or its loop_count >= 3 with composite unchanged), the sweep emits a
  HIGH-severity alert and proposes auto-acceptance via the existing
  user_overrode=0 mechanism with a marker note ("auto-swept by
  review-queue-sweep: LOOP stalled N iterations, composite unchanged;
  reviewer attention recommended before any push from this cycle's
  session_id"). Never auto-accepts — only surfaces with severity.

This:
  • does NOT change the reviewer timeout (operator-excluded decision)
  • does NOT touch the parked class (separate issue, [queue/2]'s scope)
  • uses the existing sweep infrastructure (extends, not replaces)
  • has a measurable delta: count of surfaced "stalled LOOP" alerts
    per day vs the LOOP silent-fail backlog size
  • is the cheapest stage that produces a real number for the
    24h-after comparison.

NOT in this stage-1 fix (deferred to [queue/2] or later stages):
  • Ship E1 wiring (close-gate review trigger)
  • Address the parked class (remedy 2/3 in the October list)
  • Correct mis-projected slices (remedy 5)
  • Cancel leaked doctor-probe rows + honest probe (remedy 4)
